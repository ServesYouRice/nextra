# T29 — Reject fMP4 boxes whose declared size is smaller than their header

<model>
Model: `claude-sonnet-5`
Effort: `high`
Card: T29 in `../KANBAN.md`
Depends on: none
</model>

<role>
You are a Node.js engineer working on a binary stream parser at a trust
boundary. You prove both malformed-size defects with red tests, then add the
smallest guards that guarantee the parser always advances or rejects.
</role>

<context>
`lib/fmp4Parser.js` incrementally parses FFmpeg stdout into an init segment and
`moof` + `mdat` fragments. A malformed declared size must fail closed with the
actual size in its diagnostic; accepting a size smaller than the header can
desynchronise the stream or prevent the parsing loop from making progress.

Two related defects are verified in `_parseBoxes()`:

- A normal box declaring size 4 is consumed as four bytes even though its header
  is eight bytes. The next iteration reads ASCII `styp` as a size and reports the
  unrelated number 1937013104.
- A box using the 64-bit marker (`size === 1`) is decoded without checking that
  its resulting size covers the 16-byte extended header. A declared extended
  size of 8 consumes half the header and then reports a size-0 error. A declared
  extended size of 0 leaves `_readOffset` unchanged, so the `while` loop cannot
  make progress.

The complete invariant already exists in `_readBoxHeader()`:
`size < headerSize` is invalid, and `headerSize` is 8 or 16. `_parseBoxes()` must
apply the same invariant to its streaming buffer without being refactored into
that nested-box helper.

`tests/fmp4Parser.test.js` currently contains one video-track tagging test and
fixture helpers for MP4 boxes. Preserve it unchanged.
</context>

<files>
Read: `lib/fmp4Parser.js` — `_parseBoxes`, `_handleBox`, and `_readBoxHeader`
Edit: `lib/fmp4Parser.js` — add minimum-size rejection for normal and extended headers
Edit: `tests/fmp4Parser.test.js` — add malformed-input, boundary, and recovery tests
Do not touch: `lib/ffmpegRelay.js` — the parser caller's contract is unchanged
Do not touch: `src/lib/fmp4RelayPlayer.js` — browser parsing is a separate surface
</files>

<task>
Reject every top-level MP4 box whose decoded declared size is smaller than the
header used to encode it. Emit an error naming the real declared size, clear the
current buffered input, and leave the parser usable for a later valid fragment.
</task>

<steps>
Order is load-bearing because both defects must fail against the current source
before any parser behavior changes.

1. Add two regression tests and no source change yet:
   - after a valid init segment, a normal `styp` box declaring size 4 emits an
     error naming `4` and header size `8`;
   - after a valid init segment, a complete 16-byte extended `styp` header whose
     decoded size is 8 emits an error naming `8` and header size `16`.
2. Run the focused test and quote both failures. Stop if either test passes.
3. Add two focused guards in `_parseBoxes()`:
   - after handling `boxSize === 0`, reject a non-marker normal size below 8;
   - after reading a marker's 64-bit value, reject a decoded extended size below
     16 before waiting for or copying the box.
   Follow the existing error path: emit `error`, reset `_bufferLength` and
   `_readOffset` to zero, then break. Keep marker value `1` valid until its
   extended size has been read.
4. Re-run the two regressions and confirm they pass.
5. Add the remaining cases:
   - normal size 0 retains the existing "extends to EOF" error;
   - table-test normal declared sizes 2 through 7; reuse the size-4 regression
     row and assert every value is named in its own below-8 diagnostic;
   - extended declared sizes 0 and 15 are rejected with their actual values;
   - an extended size of exactly 16 is accepted as the lower valid boundary;
   - normal and extended sizes above `MAX_BOX_SIZE` retain their respective
     existing oversize errors;
   - a second `moof` before `mdat` emits the existing incomplete-fragment error;
   - `mdat` without `moof` emits the existing missing-`moof` error and no fragment.
6. For every rejected-size and fragment-order case, feed a well-formed
   `moof` + `mdat` pair afterwards and assert one fragment is emitted. Initialize
   the parser before malformed streaming boxes so recovery is tested in the
   production state rather than the init accumulator.
</steps>

- Do not weaken, skip, or delete an existing test.
- Match the surrounding CommonJS and four-space-indentation style.
</constraints>
