# T39 — Cover WHEP transport allocation, success, and failure cleanup

<model>
Model: `claude-sonnet-5`
Effort: `high`
Card: T39 in `../KANBAN.md`
Depends on: none
</model>

<role>
You are a Node.js integration-test engineer auditing native-resource ownership.
Inject failures at each asynchronous allocation boundary and prove no transport,
consumer, session, or capacity reservation survives a failed POST.
</role>

<context>
`POST /whep/watch/:roomCode` allocates in stages: reservation, transport,
transport connection, required video consumer, optional audio consumer, session
registration, and consumer resume. Separate cleanup paths exist before and after
registration, but direct route coverage currently exercises only a successful
video-only request and final room destruction.

Existing behavior:

- missing DTLS returns 400 before transport creation;
- no shared video codec returns 415 before transport creation;
- transport-connect failure returns 500 `Transport connect failed`;
- video codec incompatibility after transport returns 415 and closes transport;
- allocation exceptions return generic 500 and close allocated resources;
- optional audio allocation failure continues video-only;
- a post-registration exception cleans through `closeWhepSession()`;
- success returns 201 SDP, registers one session, resumes consumers, and exposes
  a Location with the opaque id.
</context>

<task>
Add a fresh-harness HTTP matrix for WHEP allocation boundaries plus one fully
asserted success. After each rejection, all resources, maps, viewer counts, and
reservations must be back at baseline.
</task>

<steps>
- Build a per-case harness with active video/audio producers,
  `WHEP_ENABLED=true`, high limits, unique IP, and configurable fake router,
  transport, and consumers. Use video-plus-audio SDP when expecting audio.
  Track close/resume counts per object.
- Success:
  - factory receives `{ purpose: 'whep' }`;
  - `connect()` receives DTLS parsed from offer;
  - video/audio consumers are created paused and resume once;
  - response is 201 `application/sdp`, has answer body and
    `Location: /whep/watch/<32 lowercase hex>`;
  - same session exists in room/global maps, viewer count is one, pending zero.
- Fresh-harness failure rows:
  - offer without fingerprint: 400 `No DTLS fingerprint in offer`, no transport;
  - no shared video codec: 415 offer-codec error, no transport;
  - factory rejects: generic 500 and reservation released;
  - `transport.connect()` rejects: 500 connect error, transport closes once;
  - `canConsume()` false for video: 415 producer codec mismatch, transport closes;
  - required video `consume()` rejects: generic 500, transport closes;
  - audio `consume()` rejects after video: still 201 video-only, video resumes;
  - video `resume()` rejects after registration: generic 500, registered session
    removed and every allocated consumer/transport closes exactly once.
- Every row asserts room pending zero and global pending back at start. Rejected
  rows assert zero active sessions/viewers.
- Destroy successful rooms in `finally`, close server, restore config, and
  assert final close counts.
</steps>

<constraints>
- Scope: create only `tests/whepRoutesSession.test.js`.
- Use exact purpose options and targeted resource assertions, not object snapshots.
- Fake consumers/transports are EventEmitters with exactly the fields/methods
  the route uses and observable close counters.
- Do not assert logger output.
- Declare cases `{ concurrency: false }`; use unique rooms/IPs.
- Never leave a 201 session alive after a test.
- Do not weaken cleanup assertions or edit production source.
</constraints>

<acceptance_criteria>
- Success asserts response, SDP, Location, purpose, connect input, registration,
  resume counts, viewer count, and zero pending.
- Pre-transport 400/415 and factory-rejection paths allocate nothing and release
  reservation state.
- Every rejected stage returns exact contract and leaves zero sessions/viewers.
- Every created resource closes exactly once on its failure path.
- Audio allocation failure alone continues as 201 video-only.
- Post-registration resume failure uses registered-session cleanup.
- All singleton counters/maps return to per-test baseline.
- `git diff --name-only` lists only `tests/whepRoutesSession.test.js`.
</acceptance_criteria>
