# T32 — Cover the two browser media denial paths

Card: T32 in `../KANBAN.md`
Depends on: none
</model>

<role>
You are a Playwright test engineer. You assert what the user can see and reach—
role, accessible name, enabled state—not internal component state, and avoid
fixed waits in favor of web-first assertions.
</role>

<context>
Nextra's browser suite has 52 project-expanded cases across two spec files but
does not cover two common field failures.

Verified facts you do not need to rediscover:

- `tests/browser/media-flow.spec.mjs` already covers `getDisplayMedia` being
  undefined: the capability-preflight path.
- Missing is the runtime case where the API exists but the user dismisses the
  picker and it rejects with `NotAllowedError`.
- Also missing is `HTMLMediaElement.play()` rejecting with `NotAllowedError`
  under autoplay policy. `src/WatchView.jsx` retries muted and exposes an unmute
  control.
- `page.addInitScript(...)` is already used to install media stubs before page
  scripts run. Reuse that approach and existing role-based locators.
- `playwright.config.mjs` restricts `mobile-chrome` to
  `ui-semantics.spec.mjs`; each `media-flow.spec.mjs` test is listed only once in
  desktop Chromium. Two new tests therefore take the inventory from 52 to 54.

Out of scope:

- Forcing WebRTC-to-relay fallback by blocking UDP: no deterministic Playwright
  hook exists here, and a timing approximation would be flaky.
- A mobile settings drawer: no such component exists; narrow reflow is already
  covered in `ui-semantics.spec.mjs`.
- Adding `@axe-core/playwright`: a new dependency is outside this test-only card.
</context>

<task>
Add one Playwright test where `getDisplayMedia` rejects with `NotAllowedError`
and one where `HTMLMediaElement.play()` rejects once with `NotAllowedError`.
Assert the real user-visible recovery in both paths.
</task>

<steps>
Order is not load-bearing; the tests are independent.

- Capture denied: install an init script making
  `navigator.mediaDevices.getDisplayMedia` reject with
  `new DOMException('Permission denied', 'NotAllowedError')`. Visit `/#host`,
  click Start Sharing, then assert:
  - the alert text matches the actual copy in `src/HostView.jsx`;
  - Start Sharing is enabled again and not stuck busy;
  - `/api/metrics` reaches `rooms.active: 0`, using `expect.poll` like the
    existing preflight test.
- Autoplay blocked: override `HTMLMediaElement.prototype.play` in the viewer to
  reject once with `NotAllowedError`, then delegate to the original on later
  calls. Start a host and join with the existing helpers, then assert playback
  begins muted, the unmute button is reachable by role/name, and clicking it
  leaves the video element unmuted.
- Use web-first assertions and `expect.poll`; do not use `waitForTimeout`.
</steps>

<constraints>
- Scope: append two tests to one spec file. Change no source or config file.
- Reuse `startHost` and `joinAndWatch`; do not duplicate room setup.
- Locate controls by role and accessible name. Add no test-only DOM hooks.
- Take alert copy from source rather than guessing.
- Scope the `play()` override to the viewer page; reject once, then call the
  original so it cannot leak within the test.
- Do not weaken, skip, or delete an existing test.
- Match the surrounding `.mjs` Playwright style.
</constraints>

<acceptance_criteria>

- Autoplay denial asserts muted playback, reachable unmute control, and unmuted

- Neither test uses `waitForTimeout`.
- `npx playwright test --list` reports 54 total cases, not 56.
- `git diff --name-only` lists only `tests/browser/media-flow.spec.mjs`.
</acceptance_criteria>
