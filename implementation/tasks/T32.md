<role>
You are a Playwright test engineer. You assert what the user can see and reach —
role, accessible name, enabled state — not internal component state, and you

</role>

<context>
Nextra's browser suite is strong on happy paths (52 project-expanded cases across
two spec files) but has no coverage of the two most common ways browser media
fails in the field.

Verified facts you do not need to rediscover:

- `tests/browser/media-flow.spec.mjs:139` already covers `getDisplayMedia` being
  **`undefined`** — the "Screen capture is unavailable" preflight, asserted
  together with `rooms.active` staying `0`. That is capability detection.
- What is missing is the far more common runtime case: the API exists, the user
  opens the picker, and **dismisses it**. The browser rejects with a
  `NotAllowedError`. Nothing asserts what the host sees then.
- Also missing: `HTMLMediaElement.play()` rejecting with `NotAllowedError` under
  autoplay policy, which is what a viewer hits when a stream carries audio and
  the page has no user gesture yet.
- The harness for both already exists in the file: `page.addInitScript(...)` is
  used at lines 8, 58, and 140 to install `navigator.mediaDevices` stubs before
  page scripts run. Copy that approach.
- Existing tests locate controls by role and accessible name — e.g.
  `page.getByRole('button', { name: 'Start Sharing' })` and
  `page.getByRole('alert')`. Follow that; do not add test-only DOM hooks.
- Run config lives in `playwright.config.mjs`. The `mobile-chrome` project
  expands each case, which is why `--list` reports 52 for two files.

Deliberately out of scope, with reasons:

- Forcing a WebRTC-to-relay fallback by blocking UDP (`T-UI-03` in
  `testing/gap_05_frontend_browser_e2e.md`). Playwright has no deterministic
  hook for that here, and a timing-based approximation would be flaky. Separate
  card, if ever.
- The mobile settings drawer of `T-UI-04`. It does not exist — `grep -rn drawer
  src/` returns nothing. 375px reflow is already covered in `ui-semantics.spec.mjs`.
- `@axe-core/playwright`. It is a new dependency and `AGENTS.md` requires an
  approved card for that.
</context>

<task>
Add two Playwright tests: one where `getDisplayMedia` rejects with a
`NotAllowedError`, and one where `HTMLMediaElement.play()` rejects once with a
`NotAllowedError`. When this is done, both denial paths assert the real
user-visible outcome rather than only the happy path.
</task>

<steps>
Order is not load-bearing; the two tests are independent.

- Capture denied: install an init script making `navigator.mediaDevices.getDisplayMedia`
  reject with `new DOMException('Permission denied', 'NotAllowedError')`. Go to
  `/#host`, click **Start Sharing**, then assert:
  - the alert is visible and its text matches what `src/HostView.jsx` actually
    renders for this case — read the source and use that copy, do not invent it;
  - the **Start Sharing** button is enabled again and not stuck in a busy or
    "Starting…" state. This is the substance of the test: a dismissed picker
    must return the UI to idle, not strand it;
  - no room is left allocated, polling `/api/metrics` for `rooms.active` of `0`,
    the same way the existing preflight test does.
- Autoplay blocked: install an init script that overrides
  `HTMLMediaElement.prototype.play` to reject **once** with a `NotAllowedError`
  and behave normally on every later call. Start a host and join as a viewer
  using the existing `startHost` / `joinAndWatch` helpers in the file, then assert:
  - playback still begins muted rather than stalling;
  - the unmute control is present and reachable by role and accessible name;
  - clicking it results in the video element being unmuted.
- For both, prefer `expect(...)` web-first assertions and `expect.poll` over
  `waitForTimeout`. A fixed sleep is what makes browser suites flaky, and this
  suite currently has none.
</steps>

<constraints>
- Scope: append two tests to one spec file. Change no source or config file.
- Reuse the file's existing `startHost` and `joinAndWatch` helpers rather than
  re-implementing room setup.

  attributes to the React source — that would be a source change, and this card
  is assertion-only.

- Match the surrounding style: `.mjs`, `test(...)`/`expect(...)` from `@playwright/test`.
</constraints>
