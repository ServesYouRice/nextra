# T30 — Cover multi-frame Opus packets and multi-segment Ogg lacing

<role>
You are a Node.js test engineer working on codec framing. You construct byte

</role>

<context>
`lib/oggOpusMuxer.js` turns Opus RTP payloads into Ogg pages for the H.264
fallback relay. Its exact full-suite percentage varies with whether the optional
FFmpeg integration test runs (97.92% lines / 53.33% branches on the current
Windows audit host), but two structural branches still lack direct assertions.

Verified facts you do not need to rediscover:

- The TOC frame-code-3 range at `33-35` remains uncovered in the current full
  Node run.
- Lines 33-35 are inside `opusPacketDurationSamples()`: the TOC frame-code 3
  path, where the frame count comes from `packet[1] & 0x3f`, plus the
  `packet.length < 2` guard that returns `0`. Frame codes 0, 1 and 2 are already
  exercised; code 3 is not.
- Lines 74-76 are inside `OggOpusMuxer._page()`: the `while (remaining >= 255)`
  lacing loop and the `segments.length > 255` throw. An environment with FFmpeg
  may execute the loop indirectly, but no test decodes and asserts its segment
  table. A 65,025-byte payload reaches the throw through public `pushRtp`; there
  is no upstream cap in this module.
- `opusPacketDurationSamples` is exported directly from the module. Test it as a
  pure function; no RTP wrapper is needed.
- `_page` is private, but reachable through `OggOpusMuxer#pushRtp(packet)` with
  a large payload. `pushRtp` returns `null` for anything it rejects, so a
  returned Buffer is itself proof the page was built.
- `pushRtp` returns a page only when the granule advances. Advance the RTP
  timestamp between pushes or you will get `null` and misread it as a failure.

Out of scope: 32-bit RTP timestamp wraparound. `pushRtp` currently drops every
packet after a wrap, permanently. Whether it should stall, resync, or reset the
base granule is a product decision with no stated answer, not a test gap. Do not
write a test that pins the current stall as correct.
</context>

<task>
Extend `tests/oggOpusMuxer.test.js` to cover Opus TOC frame-code 3 and the
multi-segment Ogg lacing path. Both clusters must have structural assertions
that fail if the framing arithmetic changes.
</task>

<steps>
Order is not load-bearing.

- `opusPacketDurationSamples`, frame code 3: build a one-byte-TOC-plus-count
  packet where `packet[0] & 3 === 3` and `packet[1] & 0x3f` is a frame count,
  and assert the returned sample count equals `frameSamples * frameCount` for
  the config you chose. Keep the product at or below 5760.
- Same function, the ceiling: build a code-3 packet whose frame count pushes the
  duration past 5760 samples and assert it returns `0`.
- Same function, the truncation guard: a code-3 packet exactly one byte long
  must return `0` rather than reading past the end.
- Multi-segment lacing: push an RTP packet whose Opus payload is 600 bytes and
  assert the returned page's segment table. Read the segment count from byte 26
  and lacing values from byte 27 onward; assert they sum to the payload length,
  all but the last are 255, and the header starts with `OggS`.
- Table-test payload lengths 254, 255, 256, and 510. Assert exact lacing arrays
  `[254]`, `[255, 0]`, `[255, 1]`, and `[255, 255, 0]`. The exact 255 and 510
  cases are load-bearing: a `>` mutation in place of `>=` passes 254, 256, and
  600 while corrupting exact multiples of 255.
- Push a 65,025-byte valid Opus payload and assert `pushRtp` throws
  `Opus packet is too large for one Ogg page.`. Reach the existing branch only
  through the public method.
</steps>
