<context>
When the shared WebRTC server cannot be created, `createWebRtcTransport()` in
`lib/mediasoup.js` builds a per-transport `listenIps` fallback array. Two rules
in that fallback are encoded and neither is asserted:

- When media is loopback-bound (`RTC_LISTEN_IP === '127.0.0.1'`), the transport
  must announce neither `LAN_IP` nor `PUBLIC_IP`.
- When it is not loopback and `PUBLIC_IP` is set and differs from `LAN_IP`, the
  public entry is put at the front so remote viewers prefer it.

Verified facts you do not need to rediscover:

- Lines `98-110` are the fallback branch tests reach before any worker is
  initialized. T36 separately covers primary shared-server ordering and
  creation failure through exported `createMediasoupWorker()` with a fake native
  boundary.
- `createWebRtcTransport` is exported.
- `tests/mediasoupTransport.test.js` already captures the options object with a
  hand-rolled router stub. Reuse that shape.
- `config` is a mutable singleton. Save, assign, and restore in `finally`, with
  each mutating test declared `{ concurrency: false }`.
- Relevant keys are `RTC_LISTEN_IP`, `LAN_IP`, and `PUBLIC_IP`.
</context>

<steps>
Order is not load-bearing; each case sets and restores its own config.

- Loopback: `RTC_LISTEN_IP = '127.0.0.1'` with both `LAN_IP` and `PUBLIC_IP` set
  to non-loopback addresses. Assert exactly
  `[{ ip: '127.0.0.1', announcedIp: undefined }]`.
- LAN, no public: `RTC_LISTEN_IP = '0.0.0.0'`, `LAN_IP` set, `PUBLIC_IP` empty.
  Assert one entry announcing `LAN_IP`.
- Public differs from LAN: set both and assert two entries with public first,
  then LAN. Use `assert.deepEqual` on the whole array.
- Public equals LAN: assert only one entry; no duplicate public candidate.
- Default purpose: call `createWebRtcTransport(router)` with no options and
  assert `initialAvailableOutgoingBitrate` is `8_000_000`.
</steps>
