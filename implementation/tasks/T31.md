<context>
`createWebRtcTransport()` in `lib/mediasoup.js` builds the `listenIps` array that
becomes a viewer's ICE candidates. Two rules are encoded there and neither is
asserted:

- When media is loopback-bound (`RTC_LISTEN_IP === '127.0.0.1'`), the transport
  must announce **neither** `LAN_IP` nor `PUBLIC_IP` — a candidate a viewer
  cannot reach is worse than no candidate.
- When it is not loopback and `PUBLIC_IP` is set and differs from `LAN_IP`, the
  public entry is `unshift`ed to the **front**, so remote viewers prefer the
  public candidate over the LAN one.

Verified facts you do not need to rediscover:

- Uncovered ranges in `lib/mediasoup.js` from a full-suite coverage run:
  `31-33 43-45 62-64 104-105`. Branch coverage is **47.83%** against 91.67% lines.
- Lines `98-110` are the `else` branch of `createWebRtcTransport` — the
  per-transport `listenIps` path. **This is the branch tests reach.** The module
  level `webRtcServer` is `null` until `createMediasoupWorker()` runs, and no
  unit test runs it, so the `if (webRtcServer)` path at line 80 is dead in tests
  and the `else` at line 92 is live. Line `104-105` is the public-`unshift`
  inside it.
- `createWebRtcTransport` is exported (line 132). `createSharedWebRtcServer` is
  **not** — see `<escalate_if>` before trying to cover lines 31-33 and 43-45.
- `tests/mediasoupTransport.test.js` already asserts host/viewer/WHEP initial
  bitrates with a hand-rolled `router` stub that captures the options object.
  Copy that stub; it is all the harness this needs.
- `config` (`config.js`) is a plain mutable object, not frozen. The repo pattern
  is save / assign / restore in a `finally`, with the test declared
  `{ concurrency: false }`. See `tests/rooms.test.js:138-170`.
- Relevant keys: `RTC_LISTEN_IP`, `LAN_IP`, `PUBLIC_IP`.
</context>

<task>
Extend `tests/mediasoupTransport.test.js` so the `listenIps` array produced for

<steps>
Order is not load-bearing; each case sets its own config and restores it.

- Loopback: `RTC_LISTEN_IP = '127.0.0.1'` with both `LAN_IP` and `PUBLIC_IP` set
  to real-looking non-loopback addresses. Assert `listenIps` is exactly
  `[{ ip: '127.0.0.1', announcedIp: undefined }]` — one entry, announcing
  nothing. This is the case that matters most: it is the one where a regression
  leaks an unreachable address to viewers.
- LAN, no public: `RTC_LISTEN_IP = '0.0.0.0'`, `LAN_IP` set, `PUBLIC_IP` empty.
  Assert a single entry announcing `LAN_IP`.
- Public differs from LAN: `RTC_LISTEN_IP = '0.0.0.0'`, `LAN_IP` and `PUBLIC_IP`
  both set and different. Assert two entries with the **public one first**, then
  the LAN one. Use `assert.deepEqual` on the whole array so both membership and
  order are pinned in one assertion.
- Public equals LAN: same but `PUBLIC_IP === LAN_IP`. Assert only one entry — the
  `config.PUBLIC_IP !== config.LAN_IP` guard at line 103 suppresses the duplicate.
- Default purpose: call `createWebRtcTransport(router)` with no options at all
  and assert `initialAvailableOutgoingBitrate` is `8_000_000`, matching the
  `purpose = 'host'` default in the signature. The existing test covers explicit
  `host`, `viewer`, and `whep` but never the defaulted call.
</steps>
