<role>

<context>
`tests/whepRoutes.test.js` proves two concurrent requests for one room cannot
both pass a one-viewer room limit. Missing are per-IP request limiting, Socket.IO
viewers contributing to room capacity, and global capacity across rooms while a
first request is pending and after it becomes active.

`sessionRegistry.tryReserveWhep()` counts active sessions and pending global
reservations. The route mirrors room pending count in
`room.whepPendingReservations`. Reuse the existing valid SDP, fake media,
promise barrier, and cleanup shapes in a new file.
</context>

<task>
Pin per-IP attempts, total room viewers, and global pending/active WHEP limits.
Prove denial happens before a second transport allocation and all reservations
return to baseline.
</task>

<steps>
- Recreate the minimal route harness with distinct rooms/IPs, disposable servers,
  and fake EventEmitter transports/consumers. Set `WHEP_ENABLED=true` and restore
  it with every config mutation.
- Per-IP rate: set max 1, POST a valid offer to an unknown room twice from one
  unique IP. First is 404 room lookup; second is 429 with
  `Too many WHEP requests`. No transport call.
- Socket viewer: add one id to `room.viewers`, set room max 1, and assert POST is
  503 `Room is full` before transport creation.
- Global pending/active in one event-driven test:
  - create two rooms with active video producers;
  - set global max 1 and room/rate limits high;
  - pause the first room's factory on a promise barrier;
  - after entry, assert one pending global and one pending in room A;
  - room B POST returns 503 `Server WHEP capacity reached` with no second call;
  - release A, assert 201, zero pending, one active;
  - retry B and assert the same global 503, now due to the active session.
- In every `finally`, release barriers, destroy rooms, close server, restore
  config, and assert global/room active and pending counts return to baseline.
</steps>

<constraints>
- Scope: create only `tests/whepRoutesLimits.test.js`.
- Use promise barriers, not sleeps, polling, or `setTimeout`, to order requests.
- Assert status and distinguishing room/global error text.

- Declare all cases `{ concurrency: false }`.
- Use unique IPs; do not expose or clear the private rate map.
- Do not edit source or weaken existing tests.
</constraints>

- Pending and active singleton/room counters return to baseline.
- No timing sleep establishes ordering.
- `git diff --name-only` lists only `tests/whepRoutesLimits.test.js`.
</acceptance_criteria>
