<task>

<steps>
Order is not load-bearing.

- Table-test `buildLiveOutputPatch` across the cross product of encoder kind
  (`nvenc`, `x264`, `amf`, `qsv`, and one unrecognized kind) and video codec
  (`h264`, `av1`). For each cell assert the **entire** returned object with
  `assert.deepEqual`, not individual keys — a per-key assertion will not catch
  an unexpected extra field. Cover specifically:
  - `nvenc` + `h264` carries `tune: 'll'` and `profile: 'high'` on top of the
    common fields, plus `lookahead: false`, `multipass`, `preset2`.
  - `nvenc` + `av1` carries the same common fields but neither `tune` nor
    `profile`.
  - `x264` + `h264` carries `preset`, `profile: 'high'`, `tune: 'zerolatency'`,
    `x264opts: 'bframes=0'`.
  - `x264` + `av1` falls through to `common` (the `&& videoCodec === 'h264'`
    guard at line 90 fails).
  - `amf` + `h264` and `qsv` + `h264` carry `profile: 'high'`; both + `av1`
    return `common` unchanged.
  - An unrecognized encoder kind returns `common` for both codecs.
- Table-test `getSimpleOutputEncoderId` over every id in the explicit map —
  `obs_nvenc_h264_tex`, `jim_nvenc`, `obs_x264`, `obs_amf_h264`,
  `h264_texture_amf`, `obs_qsv`, `obs_qsv11` — asserting the exact returned
  string. Then assert the `encoderKind` fallbacks (`nvenc`/`x264`/`amf`/`qsv`)
  for an id that is not in the map, the `null` for an unknown kind, and that
  **any** input with `videoCodec` other than `h264` returns `null` (the guard at
  line 113 short-circuits before the map is consulted).
- Assert `normalizeObsEncoderRequest` returns an `error` mentioning the codec
  for an unsupported codec string, and that the codec is compared
  case-insensitively and trimmed (line 137 does `String(...).trim().toLowerCase()`).
</steps>
