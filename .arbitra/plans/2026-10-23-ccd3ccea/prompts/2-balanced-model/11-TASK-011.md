<goal>
Make the media-chunk handler derive chunk size from real binary data only, drop non-binary payloads before any buffering, parsing or forwarding, and catch any exception raised while processing a chunk.

This matters because it fixes:
- Forged chunk lengths bypass relay memory limits (high)
  <quotes> : chunk?.byteLength || chunk?.size || 0; const nextBootstrapBytes = (room.mediaBootstrapBytes || 0) + size; room.mediaBootstrapChunks.push(chunk); room.mediaBootstrapBytes = nextBootstrapBytes; </quotes> Nonbinary objects are accepted, and their client-controlled byteLength or size property is treated as their actual memory size. In the non-MP4 path, a large JSON object claiming byteLength: 1 passes the size checks and is retained while only one byte is charged to the bootstrap budget. Buffering happens even without relay viewers.
- media-chunk accepts non-binary payloads based on client-supplied byteLength/size and has no try/catch (medium)
  For anything that is not a Buffer or ArrayBuffer, the size comes from chunk.byteLength or chunk.size, which the client controls. A plain JSON object such as {byteLength: 10} therefore passes both the empty-chunk and oversize checks. That object is then passed to room.relayMp4.push or stored as room.initChunk, which is later served to viewers. The handler is synchronous with no try/catch, so if downstream parsing throws on a non-Buffer value, the exception escapes the socket.io listener.
</goal>
