<goal>
Ensure no socket.io handler in lib/socket.js destructures client-controlled payloads outside its try block, so explicit null (or other non-object) payloads produce the handler's normal invalid-parameter failure instead of an uncaught exception or unhandled rejection.

This matters because it fixes:
- Null socket payloads throw before handler error protection (high)
  <quotes> socket.on('close-viewer-transport', ({ transportId } = {}, callback) socket.on('connect-transport', async ({ transportId, dtlsParameters } = {}, callback) </quotes> The handlers destructure their arguments before entering their try blocks. The default object handles undefined, not an explicit null. Sending null therefore throws outside the synchronous close handler's catch, or rejects the asynchronous handlers before their catches run. This occurs before room membership checks.
- Null socket payloads throw before request error handling (high)
  <quotes> lib/socket.js:1835-1836 socket.on('reclaim-host', ({ code, hostToken, reloadRecovery = false } = {}, callback) => { try { lib/socket.js:1898-1899 socket.on('join-room', async ({ code, passphrase } = {}, callback) => { try { </quotes> The default object applies only to undefined, not null. Destructuring a client-supplied null throws before either try block is entered. The synchronous reclaim handler therefore leaks an exception; the async join handler returns an unhandled rejected promise. Neither path requires room membership.
</goal>
