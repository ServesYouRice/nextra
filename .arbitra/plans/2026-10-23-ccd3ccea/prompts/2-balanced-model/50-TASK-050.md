Suggested model: a balanced model (such as Claude Sonnet), effort medium. Why: Scope: a single helper with mechanical call-site updates; Asynchrony: AbortController and body-stream semantics; Testability: high with a local HTTP server; Blast radius: the CI smoke harness

<goal>
Make every smoke-packaged.js HTTP check apply its timeout across headers and body consumption.

This matters because it fixes:
- HTTP timeout does not cover smoke response-body reads (medium)
  <quotes> return await fetch(url, { ...options, signal: controller.signal }); } finally { clearTimeout(timer); } const response = await fetchWithTimeout(`${baseUrl}/readyz`, {}, 2000); const body = await response.json(); </quotes> Fetch resolves when response headers arrive, so fetchWithTimeout clears its abort timer before callers consume the response body. Subsequent json() and text() calls are outside the timeout. A server that sends headers but never completes its body can leave a stage pending indefinitely, preventing execution from reaching cleanup.
</goal>
