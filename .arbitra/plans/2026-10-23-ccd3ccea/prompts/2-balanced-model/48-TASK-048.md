<goal>
Make scripts/benchmark-runtime.js always stop ack loops, close sockets and exit on failure, and evaluate the required topology against every measured sample.

This matters because it fixes:
- Benchmark leaves sockets and ack loops running on any error, so a failed run hangs instead of exiting (medium)
  main() opens every client socket before the first metrics request. It closes them only on the success path. Each of these failures makes main() reject while the catch handler only sets process.exitCode: - connectClient() rejects for any one socket (Promise.all). - The initial fetchMetrics() throws, e.g. a non-OK status. - Any fetchMetrics() inside the sampling loop throws. The already-connected socket.io websockets stay open and keep the event loop alive. For mid-run failures, 'running' is never set to false, so the ack loops keep emitting requests every ackIntervalMs forever.
- Benchmark validates required load only at the final sample (medium)
  <quotes> rooms: last.metrics.rooms?.active || 0, producers: last.metrics.sockets?.counters?.activeProducers || 0, consumers: last.metrics.rooms?.totalMediasoupConsumers || 0, const failures = evaluateTopology(observedTopology, requirements); </quotes> Required room, producer, consumer, relay-viewer, and pipeline counts are checked only against the last sample, while performance statistics cover the broader measurement window. A topology that is missing or underloaded for most of that window can recover just before the final sample and pass with artificially favorable performance measurements.
</goal>
