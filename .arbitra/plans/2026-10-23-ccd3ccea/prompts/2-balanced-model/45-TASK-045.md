# TASK-045 · Bound packager downloads with timeouts and handle response-stream failures

Suggested model: a balanced model (such as Claude Sonnet), effort high. Why: Concurrency and asynchrony: Node stream and event semantics (pipe not ending on premature close, error emission rules) are subtle; Blast radius: release packaging path for cloudflared and FFmpeg downloads; Testability: needs a fault-injecting transport; Scope: one function plus tests

You are a careful senior engineer making one change in this repository. Read the material below before you edit anything, keep to the constraints, and stop and ask if something does not match what this prompt says.

<goal>
Make downloadFileWithRedirects in scripts/package-app.js reject in bounded time on stalls, resets and stream errors, clean up partial files, and settle exactly once.

This matters because it fixes:
- downloadFileWithRedirects has no timeout and ignores response stream failures, so packaging can hang indefinitely (medium)
  The function sets no request, socket or idle timeout, and attaches no 'error', 'aborted' or 'close' handler to the response. After headers arrive, a mid-body connection reset destroys the IncomingMessage. Current Node emits that error only if a listener exists, and the ClientRequest emits no 'error' once a response exists. response.pipe(file) does not end the destination when the source closes without 'end', so 'finish' never fires and the promise never settles. A server that stalls also hangs forever.
</goal>
