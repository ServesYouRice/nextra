<goal>
Make getTrustedForwardedClientIp derive the client only from the rightmost X-Forwarded-For entry, which the trusted loopback proxy appends. It must never read CF-Connecting-IP, whose provenance this task cannot establish. When a loopback-proxied request carries forwarding evidence but no usable rightmost X-Forwarded-For value, it must fail closed to the non-local 'unknown' sentinel. Make isIpInTrustedLan reject empty, zero or malformed prefixes instead of matching every IPv4 address.

This matters because it fixes:
- Trusted forwarded client IP is read from client-controllable headers (CF-Connecting-IP passthrough, leftmost X-Forwarded-For) (high)
  Forwarded headers are trusted when the opt-in flag is set and the immediate peer is loopback. In that case getTrustedForwardedClientIp returns the CF-Connecting-IP header verbatim if it is present. Otherwise it returns the first (leftmost) X-Forwarded-For entry. The code only checks that the TCP peer is loopback. It never checks that the proxy set or sanitized these headers. Generic local reverse proxies such as nginx and Traefik pass a client-supplied CF-Connecting-IP header through unchanged. nginx's common $proxy_add_x_forwarded_for appends the real address to the right of whatever the client sent, so the leftmost entry is chosen by the attacker. A remote client can therefore claim to be 127.0.0.1 or a trusted-LAN address, and classifyClient will report kind 'loopback' or 'trusted-lan'.
- A trusted-LAN CIDR entry with an empty prefix (e.g. '192.168.1.0/') is parsed as /0 and trusts every IPv4 address (medium)
  isIpInTrustedLan splits each entry on '/' and converts the prefix with Number(prefixText). Number('') evaluates to 0, which passes the Number.isInteger check and the 0..32 range check. A prefix of 0 produces mask 0, so the masked comparison is true for every valid IPv4 address. A trailing-slash typo or empty prefix therefore turns the allowlist into a match-all rule instead of being rejected. An explicit '/0' is also accepted silently.
</goal>

<context>
- lib/network.js getTrustedForwardedClientIp currently does `const cfConnectingIp = parseForwardedFirst(headers['cf-connecting-ip']); if (cfConnectingIp) return normalizeIp(cfConnectingIp); const forwardedFor = parseForwardedFirst(headers['x-forwarded-for']);`. parseForwardedFirst returns `value.split(',')[0].trim()`, which is the leftmost hop and is chosen by the client.
- shouldTrustForwardedHeaders only checks that the TCP peer is loopback. It cannot tell cloudflared from nginx, Traefik or any other local proxy that relays a client-supplied CF-Connecting-IP unchanged (critique PC-005-CF-FALLBACK). This task therefore must not honour CF-Connecting-IP in any case, including when X-Forwarded-For is absent. Cloudflare provenance is decided in section-49e0545c60d121dd3e784d86/Q-001 and implemented by TASK-094.
- Standard proxies (nginx $proxy_add_x_forwarded_for, Caddy, Traefik, and the Cloudflare edge as relayed by cloudflared) append the address they observed on the right. With a single trusted loopback proxy, the rightmost entry is the only one the proxy vouches for.
- normalizeIp already returns the sentinel 'unknown' for invalid input. classifyClient maps 'unknown' to kind 'remote', and isLocalClientIp('unknown') is false. Returning 'unknown' is therefore fail-closed for classification. Returning '' is likely to make callers fall back to the loopback TCP peer, which would classify a proxied remote user as 'loopback'.
- isIpInTrustedLan: `const prefix = Number(prefixText); if (... !Number.isInteger(prefix) || prefix < 0 || prefix > 32) return false; const mask = prefix === 0 ? 0 : ...`. Number('') is 0, so '192.168.1.0/' matches every IPv4 address.
- The existing test 'forwarded headers are trusted only from loopback proxy peers' expects '198.51.100.22' (CF-Connecting-IP) for headers { 'cf-connecting-ip': '198.51.100.22', 'x-forwarded-for': '203.0.113.44, 10.0.0.1' }. Under the new rule it must expect '10.0.0.1'. This intentionally reverses the behaviour that C-70eb68e12178 reports.
- lib/network.js declares `const crypto = require('crypto');` after module.exports. It is used only at call time, so leave it as is unless the edit requires moving it.
</context>
