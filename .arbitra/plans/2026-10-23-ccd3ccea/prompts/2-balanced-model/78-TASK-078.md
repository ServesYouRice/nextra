<goal>
Journal a captured inverse whenever a mutation was dispatched, even if its response times out, and restore unset profile parameters by deleting them.

This matters because it fixes:
- A timed-out mutation loses its already-captured rollback state (medium)
  <quotes> src/lib/obsWebSocket.js:87-88 pendingRequests.delete(requestId); reqReject(new Error(`OBS request ${requestType} timed out after ${requestTimeoutMs}ms.`)); src/lib/obsWebSocket.js:475 const inverse = await snapshotMutation(requestType, requestData); src/lib/obsWebSocket.js:485-489 const response = await sendRequest(requestType, requestData); if (!successfulResponse(response)) return response; if (inverse) { rollbackSteps.push(inverse); </quotes> An OBS mutation can take effect even if its response arrives after the request timeout. Although its inverse was captured before dispatch, it is journaled only after a successful response. A timeout throws past that insertion, so rollback silently omits the possibly applied mutation and can report no rollback failures.
- Rollback of profile parameters that were unset writes an empty string instead of restoring the default (medium)
  For a parameter with no user value, GetProfileParameter returns parameterValue null, and OBS uses defaultParameterValue. The snapshot turns null into '' and rollback writes that empty string. In v5, sending parameterValue null deletes the parameter instead. The result is that a 'rollback' replaces OBS defaults with explicit empty values. Affected keys include AdvOut Encoder, SimpleOutput VBitrate and StreamEncoder, Stream1 IgnoreRecommended, AdvOut ApplyServiceSettings and Video ColorSpace/ColorRange. OBS reads those as 0, false or an empty encoder id.
</goal>
