<goal>
Stop showing the synchronous PowerShell dialog from uncaughtExceptionMonitor. Report fatal failures once, from the exit path, with wording that does not mislabel runtime crashes as startup failures.

This matters because it fixes:
- uncaughtExceptionMonitor shows a synchronous 15-second PowerShell modal, even for exceptions the app may recover from, and reports runtime crashes as startup failures (medium)
  Node emits 'uncaughtExceptionMonitor' for every uncaught exception before any 'uncaughtException' listener runs, whether or not the application then handles it and continues. The handler calls showFailureDialog(). That function uses execFileSync to start powershell.exe and show a WScript Popup with a 15-second timeout, which blocks the Node main thread until the user dismisses it or the timeout elapses. Consequences: - If the server installs a recovering uncaughtException handler (outside this scope), the first runtime exception freezes all HTTP and signalling work for up to 15 s plus PowerShell start-up time. - The dialog tells the user 'Nextra could not start correctly' while the app keeps running. - Any non-zero exit at any time, not only during startup, produces the same startup-failure dialog.
</goal>
