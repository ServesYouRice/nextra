<goal>
Explicit Leave Room (and other terminal session resets) must invalidate any pending join or reconnect, so a stale completion never restores the joined state or starts playback.

This matters because it fixes:
- An in-flight reconnect can undo an explicit Leave Room (medium)
  <quotes> src/WatchView.jsx:905 await device.load({ routerRtpCapabilities: rtpCapabilities }); src/WatchView.jsx:923 setJoined(true); src/WatchView.jsx:1181 await socketRequest(socket, 'leave-room', {}, { timeoutMs: 5000, maxAttempts: 1 }); src/WatchView.jsx:1191 setJoined(false); src/WatchView.jsx:1237 const response = await joinRoomAndLoadDevice(roomCode); </quotes> Reconnect leaves the joined UI available while awaiting room rejoin and device loading. Leave Room can therefore complete during that wait. The pending join helper has no session-generation or cancellation check before restoring the room refs and setting joined true, and reconnect can subsequently attempt playback. The UI can return to a joined state even though the server has already processed the leave.
</goal>
