<goal>
Stop the infinite reload loop on persistent chunk-load failures, including failures of lazy chunks requested after the app has mounted. Do this with a reload budget kept in sessionStorage that only time-window expiry resets, never app mount.

This matters because it fixes:
- Unbounded reload loop on persistent chunk loading failures (high)
  Chunk load error recovery relies solely on an in-memory boolean flag `reloadScheduled`. When `window.location.reload()` executes, the page completely reloads and resets the JavaScript execution context along with `reloadScheduled`. If a dynamic chunk fails to load persistently (such as after a deployment where old chunks are deleted, or during a persistent network issue), the page enters an infinite reload loop.
</goal>

<context>

- reloadScheduled lives only in memory, and window.location.reload() resets it, so a persistent chunk failure reloads forever.
- Critique PC-075-PREMATURE-BUDGET-RESET: a successful mount does not prove that lazy chunks requested later will load. A failure after mount can reload, mount again, and, if mount clears the budget, repeat forever. The budget must therefore survive mount and expire only by time.
- VAL-106 says the guard 'resets after a successful load'. That clause is superseded by VAL-145/VAL-146 and must not be implemented.
</context>
