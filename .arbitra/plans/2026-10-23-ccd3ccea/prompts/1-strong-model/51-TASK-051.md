This matters because it fixes:
- Packaged smoke can validate and shut down the wrong instance (medium)

<steps>
1. Before spawning, probe `${baseUrl}/healthz` with a short timeout. Any HTTP response means the port is occupied, so throw. Only a connection refusal proceeds.
2. Do not use a single abort signal that fires on any child exit. Export a pure `classifyChildExit({ phase, code, signal })` returning 'unexpected' | 'tolerated-recovery' | 'expected'. Phases are 'starting', 'stages', 'recovery', 'post-recovery', 'shutdown' and 'cleanup'. A child 'error' event is always unexpected. Any exit in 'starting' or 'stages' is unexpected. In 'recovery' and 'post-recovery', an exit with code 0 and no signal is 'tolerated-recovery'; any other code or a signal is unexpected. Any exit in 'shutdown' or 'cleanup' is 'expected' and only recorded.
3. Export `createChildExitMonitor(child)`. It records the first exit as { code, signal, phase, at } and exposes `setPhase(phase)`, `phase`, `record`, `exited` (a promise that always resolves with the record and never rejects) and `unexpected` (a promise that rejects only when classifyChildExit returns 'unexpected', including for 'error'). Attach a no-op catch to `unexpected` internally so that a rejection nobody races is never an unhandled rejection. Stages race against `unexpected`, never against raw exit.
4. Phase transitions: start in 'starting'. Set 'stages' after readiness passes. Call setPhase('recovery') immediately before POST /api/test/kill-media-worker. Call setPhase('post-recovery') after the replacement is adopted. 'post-recovery' keeps the code-0 tolerance in case the stub's exit is delivered late. Later stages detect a dead server through HTTP failures and owned-PID checks. TASK-052 sets 'shutdown' and 'cleanup'.
5. In checkMediaWorkerReplacement, do not require the child to still be running. Success requires readiness plus an adopted replacement PID. If the deadline passes without adoption, include the recorded child exit (if any) in the failure message.
6. Change listProcesses to also return the parent PID (Win32_Process ParentProcessId; `ps -Ao pid=,ppid=,args=`). Add an exported pure `isDescendant(pid, rootPid, records)`.
7. Maintain an `ownedPids` set seeded with child.pid. After readiness, require metrics.process.pid to be a descendant of child.pid, then add it. After worker recovery, adopt the new metrics.process.pid only if the port was never observed unowned and the process's command matches the same caxa applications/nextra-<id> directory as the originally owned process. Otherwise fail. Ancestry may be broken at this point, because the child may already have exited.
8. Expose the monitor and ownedPids to later stages (for example via a run context object passed to runStages) so TASK-052 can reuse them without re-deriving state.
9. If section-a9280f1cb8fa879913f0582c/Q-001 says the PS1 is still used, add the equivalent pre-launch port check. Check $process.HasExited only while the harness is outside the recovery and shutdown phases. Otherwise leave the PS1 untouched.
</steps>
