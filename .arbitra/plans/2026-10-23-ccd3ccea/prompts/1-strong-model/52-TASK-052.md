<goal>
Ensure smoke cleanup kills only processes the run owns, fails when process enumeration fails, always terminates the child through its handle, and reports processes that survive graceful shutdown as failures. The shutdown stage treats the requested child exit as its success condition rather than as an unexpected exit.

This matters because it fixes:
- Smoke cleanup can kill unrelated concurrent Nextra instances (medium)
  <quotes> if (CAXA_PATTERN.test(command)) return true; process.kill(pid, 'SIGKILL'); $remaining = @(Get-SmokeProcesses | Where-Object { $baselineProcessIds -notcontains $_.ProcessId }) foreach ($candidate in $remaining) { Stop-Process -Id $candidate.ProcessId -Force -ErrorAction SilentlyContinue </quotes> Cleanup identifies processes using a shared Nextra caxa-path pattern and excludes only PIDs observed before launch. It does not establish process ancestry or another run-specific identity. Any unrelated matching instance started after the baseline is therefore eligible for forced termination. The baseline protects pre-existing processes, not concurrently started ones.
- Smoke process enumeration fails open, so leftover-process checks can pass without checking anything and CI can hang (medium)
  listProcesses() returns [] in several failure cases: PowerShell or ps exits non-zero, stdout is empty, output exceeds the 8 MiB maxBuffer (spawnSync then sets result.error to ENOBUFS and status to null), or the JSON does not parse. cleanup() then finds nothing to kill and nothing stale and returns null. The stale-extraction and lingering-cloudflared assertions therefore pass without checking anything. The spawned child is never killed directly through its handle. If enumeration fails, the packaged process tree stays alive and the referenced ChildProcess keeps Node's event loop running, so the script does not exit. If only the baseline enumeration fails, every caxa nextra- process is SIGKILLed, including pre-existing instances the baseline was meant to protect.
- Graceful-shutdown stage never asserts process exit, and cleanup silently force-kills survivors (medium)
  checkGracefulShutdown discards the shutdown response and sets stopped = true on any fetch exception, including the 1 s abort timeout. A server that is alive but unresponsive therefore counts as stopped. cleanup() then SIGKILLs every new smoke process before it checks for stale ones. A process tree that never exits after shutdown is killed and the run still passes. The child's exit code is never observed. The PowerShell version has the same structure: Stop-Process -Force runs before the stale check.
</goal>
