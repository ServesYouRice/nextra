<goal>
Make handleStartSharing failures on a resumed room non-destructive when they happen before media is produced, and prevent changing ingest mode while a recovered room awaits resume.

This matters because it fixes:
- Cancelling the screen picker on 'Resume Sharing' emits host-stopped and destroys the reclaimed room (medium)
  In browser-mode reload recovery, the mount effect has already reclaimed host ownership of the room ('reclaim-host') and set resumePending, and the button reads 'Resume Sharing'. handleStartSharing then calls getDisplayMedia, and every failure, including a NotAllowedError from the user dismissing or cancelling the picker and preflight blockers, lands in the same catch. That catch unconditionally emits 'host-stopped' and calls cleanup(). cleanup() also clears resumeRoomRef and the stored recovery session. A single cancelled picker therefore permanently ends the room that viewers were waiting in, which defeats the feature whose hint promises the host only needs to 'select again'.
- Recovery permits changing ingest mode without replacing the room (medium)
  <quotes> setIngestMode(response.ingestMode === 'obs' ? 'obs' : 'browser'); let createdRoom = resumedRoom; if (!createdRoom) { setIngestMode(mode); </quotes> Browser-room recovery leaves the view idle with Resume Sharing pending, so ingest-mode settings remain available. Changing to OBS updates local state but leaves resumeRoomRef intact. Starting then reuses the recovered browser room, skips create-room, and follows the OBS path without communicating the changed room mode to the server.
</goal>
