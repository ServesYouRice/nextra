<goal>
Requests relayed from a loopback peer by the built-in cloudflared tunnel must never be treated as the local operator. cf-connecting-ip must not let direct non-loopback clients choose their own rate-limit identity. Direct local and trusted-LAN operator access must keep working.

This matters because it fixes:
- Tunnel or proxy requests without Origin/Referer fall back to loopback (operator) classification when the local server runs plain HTTP (critical)
  Every request relayed by the built-in cloudflared tunnel, or by any proxy on the same host, arrives from 127.0.0.1. Only isKnownPublicShareRequest() stops such a request from being treated as the local operator, and it fails open in several ways. 1. The Host-derived candidate takes its scheme from the local socket's TLS state. getRequestHostOrigin is called with `encrypted` = req.socket.encrypted, and the server is plain HTTP when LOCAL_HTTPS is false. The tunnel forwards Host=<name>.trycloudflare.com, so the candidate becomes http://<name>.trycloudflare.com. It never matches the known https:// tunnel/share origin. 2. getForwardedOrigin needs X-Forwarded-Host as well as X-Forwarded-Proto. Cloudflare does not normally set X-Forwarded-Host. 3. The only candidates left are Origin and Referer. The client controls both and can omit them, or set Origin to an allowed local origin such as http://127.0.0.1:PORT. getClientIpFromHeaders then returns the raw loopback address (line 352). classifyClient almost certainly reports 'loopback', and isOperatorAuthorized returns true without any token. Missing proxy evidence is treated as full local trust.
- cf-connecting-ip is honoured without checking that the peer is the loopback tunnel, enabling per-IP rate-limit bypass (medium)
  The fallback branch in getClientIpFromHeaders runs whenever isKnownPublicShareRequest() is true. Unlike shouldTrustRequestForwardedHeaders, it has no isLoopbackIp(remoteAddress) check. The Host, Origin and Referer that drive isKnownPublicShareRequest are client-controlled, and the share URL is public by design. A client connecting directly to a non-loopback bind (LAN, or PUBLIC_IP mode) can therefore: - send Host or Origin equal to the share/tunnel URL; - send an arbitrary cf-connecting-ip; - receive the identity `public-share:<attacker value>`. Rotating that value gives a fresh identity on every request or socket.
</goal>
