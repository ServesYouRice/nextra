# TASK-036 · Generation-fence WHIP startup and producer commits; tear down on producer failure

Suggested model: your strongest model (such as Claude Opus), effort high. Why: Concurrency and async ordering: multiple interleaving awaits (createTransport, connect, produce) and event callbacks; State coupling: room fields, sessionRegistry, and media-pipeline ownership must stay consistent; Blast radius: the live OBS ingest path for every room; Test infrastructure: needs fake transports with deferred promises and mock timers; Reversibility: medium; behavioral regressions would affect streaming

You are a careful senior engineer making one change in this repository. Read the material below before you edit anything, keep to the constraints, and stop and ask if something does not match what this prompt says.

<goal>
Make every asynchronous step of WHIP startup and producer creation verify the session generation and transport identity before committing shared state, and tear down the current generation cleanly when producer creation fails or DTLS fails mid-creation.

This matters because it fixes:
- Asynchronous startup can publish a superseded session (high)
  <quotes> await transport.connect({ dtlsParameters: remoteDtls }); room.whipSessionId = sessionId; room.whipResourceId = resourceId; room.whipTransport = transport; room.whipProducer = await transport.produce({ </quotes> There is no cancellation or generation check after awaiting transport.connect and before publishing session state. Cancellation clears the generation and releases the startup lock, but a subsequently resolved connect can still register its resource and overwrite room state. Producer callbacks similarly assign awaited results into shared room fields and pipeline ownership before checking their generation, allowing stale completions to mutate replacement-session state.
- Producer creation failure after DTLS connect is only logged, leaving a half-initialized session that never goes live and is never torn down (medium)
  The handler sends the 201 SDP answer before any producer exists. Producers are created later, inside the async 'connected' handler. If transport.produce() rejects, the catch block only logs the error. This happens, for example, when the router rejects the audio rtpParameters derived from the offer, or when the video producer succeeds and the audio producer fails. Any producer already created stays open and owned by the media pipeline. room.whipConnected is never set, so no new-producer events or host metrics are emitted and no relay is prewarmed. Nothing closes the transport, and since DTLS stays connected the grace timer never runs. The superseded-generation branches close producers but never release the pipeline ownership taken by ownWhip(). The async handler also has a race: if DTLS fails while produce() is pending, the later 'room.whipConnected = true' overwrites the false set by the failure branch. The grace timer then sees a connected session and never tears it down.
</goal>
