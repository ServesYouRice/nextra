<goal>
After relay playback starts, overflow, SourceBuffer or MediaSource errors and append failures must stop playback cleanly, show the specific error and allow retry, without silently discarding media bytes.

This matters because it fixes:
- Relay queue overflow or SourceBuffer error after playback starts leaves the UI in watching/relay state with a frozen stream (medium)
  failRelayGeneration removes the chunk listeners and emits relay-consume-stop. It does not reset watching or playbackMode, tear down the MediaSource, or restart playback. It sets fallbackState, which belongs to fMP4 fallback mode and is not used for relay status, so the status line keeps reporting an active relay. A SourceBuffer 'error' only clears appendingLock. After an MSE parse or decode error, MediaSource leaves the 'open' state and processQueue returns early, so the failure stays silent until 240 chunks or 24MB accumulate. During startup, cleanupRelayAttempt settles firstBuffered with the generic 'cleaned up' error before settleFirstBuffered(failure) runs. The specific overflow message is therefore lost, and the caller's catch handler overwrites the displayed error.
- Relay append failures silently discard required media bytes (medium)
  <quotes> src/WatchView.jsx:522 const nextChunk = chunkQueueRef.current.shift(); src/WatchView.jsx:528-533 queuedBytesRef.current = Math.max(0, queuedBytesRef.current - nextChunk.byteLength); sourceBufferRef.current.appendBuffer(nextChunk); } catch (appendErr) { console.warn('[Nextra] appendBuffer error:', appendErr.message); appendingLock = false; } </quotes> The chunk is removed and its byte count deducted before appendBuffer succeeds. A synchronous failure, including QuotaExceededError, only logs the error, permanently losing those bytes while subsequent chunks continue to be processed. Asynchronous SourceBuffer errors likewise only clear the lock. Neither path transitions established playback into a recoverable failure state.
</goal>
