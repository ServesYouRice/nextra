<claim>
A new relay generation mid-playback is appended to the existing SourceBuffer without abort() or changeType() (medium)

onMediaInit remains subscribed after playback starts. On a new generation it flushes the JS queue and updates selectedGeneration and mimeType. The SourceBuffer created with the original mimeType is reused, though: it is not aborted to reset the parser, and it is not re-typed or recreated when the mime type changes. MediaRecorder timeslice chunks do not align with WebM cluster boundaries. The parser is therefore likely mid-cluster when the new generation's EBML header is appended, which causes a parse error and ends the MediaSource. That leads to the silent stall and overflow path described in the queue-overflow finding.
</claim>
