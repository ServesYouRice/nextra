<claim>
Coverage gate calculates directory depth incorrectly causing double slashes and universal target misses (high)

scripts/coverage-gate.js computes the indentation depth in the Node.js test coverage report by counting raw leading space characters (rawName.length - rawName.trimStart().length) and directly indexes pathAtDepth with that value. Because Node's built-in coverage reporter indents nested hierarchy rows by 2 spaces per level, depth evaluates to 2, 4, etc. instead of sequential 1, 2, leaving sparse undefined slots in pathAtDepth. Joining with '/' results in paths with double slashes (e.g. 'lib//roomMediaPipeline.js' and 'src//lib//lifecycleController.mjs'), which never match the entries in targets. Consequently, observed coverage is never collected for target files and the gate unconditionally fails.
</claim>
