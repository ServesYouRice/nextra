extra-stop-while-offline (socket lane, branch lane/socket, from dev b7eff8d, commit c07f1ad; found while carrying out run-ccd3ccea's plan, not a plan item): a host who stopped while the page's socket was down left the room up for its whole reconnect window. Real, fixed.

Cause: every host stop on the page (Stop Sharing, the unmount teardown of Leave and Stop, the capture's 'ended' handler, a start that fails after its room exists, pagehide without reload recovery) sent a bare `host-stopped`. While the socket is down Socket.IO buffers it and sends it on the next connection, before 'connect' (onconnect: emitBuffered, then 'connect'), so before any reclaim. The server's handler only ended the room found by findRoomByHost(socket.id), and the new connection is not the room's host, so it did nothing. The room stayed for HOST_RECONNECT_GRACE_MS (30 s) and viewers waited for a host who had already stopped, then got "Host reconnect window expired".

How the host token works (checked before choosing the design):
- create-room makes it (lib/rooms.js prepareRoom, 24 random bytes in hex) and returns it to the page; the page keeps it in hostTokenRef and, with reload recovery, in the sessionStorage record `nextra.hostRecovery.v1` { code, hostToken, ingestMode }.
- reclaim-host checks it with timingSafeTokenEqual (reclaimHostRoom) and keeps it: the token never rotates for the room's life. It also cannot rotate cheaply: OBS uses it as its WHIP bearer token (lib/whipRoutes.js), and the page's own reclaim retries resend the same token.
- So anyone holding the token can already end the room today (reclaim-host, then host-stopped). Honouring the token on host-stopped gives no one a new power; but the token alone cannot tell a stopped page from a newer session of the same room that another page (e.g. a duplicated tab with the copied sessionStorage record) has reclaimed since.

Design:
- `host-stopped` may carry { code, hostToken, hostSocketIds }. From the room's own host connection it works exactly as before (the payload is not looked at). From a connection that hosts no room, the server (findRoomStoppedFromAnotherConnection in lib/socket.js) ends the named room only when: the payload is an object, the code is valid, the token is a string of 16+ chars equal (timing-safe) to that room's token, hostSocketIds is an array of 1 to 16 entries, and the room's current hostSocketId is one of them. Anything else ends nothing.
- hostSocketIds are the ids of the page's latest Socket.IO connections: HostView adds socket.id at mount and on every 'connect' (rememberSocketId, last 8). A Socket.IO connection id is unique to one connection, and a connection becomes a room's host only by its own create-room or reclaim-host, so "the room is hosted from one of these" means "this page holds the room now". A page that stopped cannot end a room another page reclaimed (its host id is not in the list); a stale token of an ended room cannot end a later room with the same code (different token); a wrong, missing or other room's token ends nothing. The list also covers the case where the page reclaimed on a later connection and lost the ack (that connection's id is in the list too).
- HostView sends every host stop through sendHostStopped (hostStoppedPayload over roomCodeRef, hostTokenRef, the id list; a bare host-stopped when the page holds no room). Each call site was `socket.emit('host-stopped')` directly before cleanup(), which still runs after it, so the payload is built while the refs still hold the room. The start operation's compensating host-stopped (createStartAttempt's emitHostStopped) stays bare on purpose: startOperationGuard relies on it acting on the socket's own room.
- README: the reload-recovery paragraph's "Explicit stop still ends the room immediately" now says this holds also when the connection is down at that moment (while the page stays open).

Left open / for the owner:
- A stop made while offline reaches the server only if the page stays open until its socket reconnects; a tab closed while offline still leaves the room to its 30 s window (nothing on the page can send then).
- A start's compensating host-stopped (a stale start ending the room it just created) stays bare, so if the socket drops right then, that room (no viewers yet) lingers for the window. Giving it the room's code and token would mean changing createStartAttempt in startOperationGuard.mjs; not done (outside the stop path).
- A fresh room whose start fails in the media phase before React has synced roomCodeRef sends a bare stop (as before); roomCodeRef is set by an effect after the render, while hostTokenRef is set at once. A resumed room's code is set at once, so its failure path carries the payload.
- Files changed outside lib/socket.js and the stop path: src/lib/hostRecovery.mjs (the two helpers and a comment), README.md (one sentence), tests.
