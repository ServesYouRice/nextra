extra-capture-toggle-clip (found while carrying out run-ccd3ccea's plan; not a plan item): fixed on lane/libmisc, commit e06cd31 (message "fix(ui): show every cell of the host page's Resolution toggle on phones narrower than 365px"). Lane was at dev 96b585a.

Defect: on the host page at 320 to 364px, with OBS on or off, the capture row for Resolution (label + toggle of 4K / 1440p / 1080p) is cut off by its own toggle. The row is a grid `auto auto` (`.capture-settings .setting-row-inline`, which also beats the generic narrow-width stacking rule `.setting-row-inline { grid-template-columns: 1fr }` by specificity) and the toggle has `overflow: hidden`, so as a grid item it shrinks below its content instead of widening the row. Three 5.25rem cells are 260.4px; label + 0.6rem gap + toggle need 332.4px plus the 1rem page padding, so the row fits from 365px up (with the 62px "Resolution" label of Segoe UI). Below that the toggle is squeezed and clips the 1080p cell. Measured (Chromium): at 320px the toggle is 216px wide, its visible part ends at x=303, the 1080p cell is at 260..344, so 41px of an 84px cell (about half of its visible face, and the focus ring) is cut. At 340px: 21px; at 360px: about 1px (cell 260..344, visible to 343). The page does not scroll (document scrollWidth equals clientWidth throughout), so it cannot be reached by scrolling. Focusing the 1080p cell does not scroll the toggle either (probe `libmisc-extra-clip-focus.txt`: scrollLeft stays 0, cell stays at 260..344 with the toggle ending at 304), so a keyboard user's focused cell stays hidden.

The other toggles are fine: Frame rate (two 5.25rem cells, 176.4px beside a 63.5px label, 249px) fits from 320px; the OBS tuning-profile toggle and the live Resolution / Frame rate toggles in `.controls` (shown while sharing) were already fixed by 9ce95fa and are fully visible at every probed width. Only `.mode-toggle` exists on the host page (OBS tuning profile, Resolution, Frame rate; src/HostView.jsx), nothing else follows the row pattern.

Fix (src/index.css, 16 lines with the comment, next to the `.capture-settings` rules): `@media (max-width: 23em) { .capture-settings .setting-row-inline { grid-template-columns: minmax(0, 1fr); gap: 0.35rem; } }`. Below 23em (368px at the default font size) the label of each capture row (Resolution and Frame rate alike) sits above its toggle, which then has the row's full width (260.4px of 288px at 320px). 368px is the exact fit (365px) plus a few pixels for system fonts whose label is wider, and stays under the 375px phones, so from 375px up nothing moves. em in a media query follows the browser's default font size, as the rem cell widths do. src/HostView.jsx is untouched.
