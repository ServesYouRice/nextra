TASK-055 (lane server, commit cbcbe78 on lane/server): URLs for the app and WHIP listeners now follow the address family the listeners bound. New file lib/listenerHost.js holds the pure helpers (clientHostForBoundAddress, formatHostForUrl, isBoundToIpv6Loopback, probeHostsForBindHost); server.js records server.address() of the app and WHIP servers after listen and uses it in getHostPageUrl, getLoopbackBaseUrl, the "Local:" line, getWhipHttpClientHost/getWhipHttpBaseUrl and getAllowedOrigins ([::1] origin added when the app is on the IPv6 loopback). The already-running probe tries 127.0.0.1 as well for ::1 and both loopbacks for localhost, in parallel, 1.5 s timeout as before. Tests: three real-server integration tests failed before the fix (details in results/TASK-055.json), the IPv4 default test passed before and after; unit tests in tests/listenerHost.test.js. npm run lint, typecheck pass; npm test 515/515 in the lane.

Prompt corrections and decisions:
- server.js is not a module, so the pure helper cannot be unit-tested from it; it lives in the new lib/listenerHost.js (not one of the files the prompt names; lib/network.js and lib/portResolver.js untouched).
- '::' with "dual-stack assumed": Node binds '::' dual-stack unless ipv6Only is passed, which Nextra never does, so the helper takes { dualStack = true } and returns 127.0.0.1; with dualStack false it returns ::1. Nothing in server.js passes false, so a v6-only '::' socket (IPv4 stack disabled by the OS) is still advertised as 127.0.0.1.
- whipHttpHost stays a bare host ('::1', not '[::1]'); the host page already brackets it (HostView formatHostForUrl), and whipHttpUrl is bracketed. VAL-081's wording "point at [::1]" is met by whipHttpUrl.
- 'localhost' now follows the bound address for both listeners, as the prompt asks. On this machine (Node 22, Windows) 'localhost' binds ::1, so BIND_HOST=localhost was advertised as an unreachable 127.0.0.1 too; the localhost test covers that and passes with either family.
- A bind host of '[::1]' does bind in Node 22 (brackets are accepted), so the bracketed spelling is a real input and is handled.
- The pre-listen probe also uses the configured specific IPv4 host first (BIND_HOST=192.168.1.20 probes 192.168.1.20 then 127.0.0.1); before it probed only 127.0.0.1, which cannot reach a listener on another address. Default config probes only 127.0.0.1 as before.
- The 'Bind:' banner line still prints '::1:PORT' unbracketed; not in the prompt, left alone.
- "Check whether CI supports binding ::1": the repository has no hosted CI by the owner's rule. The ::1 integration tests detect whether ::1 can be bound and call t.skip otherwise, so they skip explicitly on a machine without IPv6 loopback.
- README config table (BIND_HOST, WHIP_BIND_HOST) not touched; no wording there contradicts the change.
