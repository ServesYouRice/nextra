extra-reclaim-pause-flake (socket lane, branch lane/socket, from dev 434fbbb, commit 617ac23; found while carrying out run-ccd3ccea's plan, not a plan item): the flaky browser test tests/browser/host-reload-recovery.spec.mjs › 'leaving the host page during the pause between reclaim attempts sends no further attempt' (added by TASK-069, c1dd9ec) shows a real defect. The test was right; the app sent a reclaim attempt after the host had left the host view.

Cause: HostView's mount effect runs reclaimWithRetry (src/lib/hostRecovery.mjs) with socketRequest as the request. After a dropped attempt the loop pauses 0.5 s, then 1 s; Socket.IO reconnects 0.5 to 1.5 s (1 s +/- 50 %, reset after each reconnect) after a drop. When the pause ended first, the next attempt began and waited inside socketRequest's waitForSocketConnect for the socket. The effect's cleanup (leaving #host) set the cancel flag and cancelled the pause, but the waiting request never looked at the flag: on reconnect Socket.IO flushed the buffered host-stopped of the unmount teardown and the request then emitted reclaim-host. The loop ignored the answer ('cancelled'), but the server had already handed the room back to that socket and cleared its reconnect timer, so a room the host walked away from was taken over again by a page that no longer shows it (viewers get host-reconnected and no stream).

Paths checked for an attempt after the leave (step 1):
- pause running at the cleanup: retryWait.cancel() wakes it and the loop stops (fine before and after);
- attempt begun, waiting for the socket to connect: sent on reconnect (the defect, fixed);
- attempt already emitted, waiting for its ack: sent before the leave; its answer is ignored and no retry follows (fine; now the wait also ends at once);
- socketRequest's own retry: the loop passes maxAttempts 1 (none);
- Socket.IO's send buffer: socketRequest only emits once connected, so no reclaim-host is buffered (only host-stopped is, by design);
- a re-run of the effect while mounted (StrictMode's replay): the old run's waiting attempt was sent too (a duplicate reclaim); covered by the same fix;
- onReconnect (the 'connect' handler) reclaims only while isSharing and is removed at unmount; not part of this path, not changed.

Fix:
- src/lib/mediasoupClient.js: socketRequest takes options.signal (AbortSignal). Aborted before or while waiting for the connection: nothing is sent; aborted while waiting for the ack: the wait ends at once and a late ack is dropped. It rejects with the new phase 'cancelled', which shouldRetry never retries. Without a signal nothing changes.
- src/lib/hostRecovery.mjs: reclaimWithRetry takes an optional signal and hands it to every attempt (the attempt options are unchanged when none is given).
- src/HostView.jsx (mount reclaim effect only): an AbortController per effect run; isCancelled reads its signal, the signal goes to reclaimWithRetry, and the cleanup aborts it (plus retryWait.cancel() as before).
- The existing flaky test is unchanged: with the fix it is no longer timing-dependent.
