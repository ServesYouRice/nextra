Notes: the prompt's step 1 says "on throw, push the inverse then rethrow"; that is done for snapshotted mutations only. A timed-out StartStream or StopStream has no captured state (its inverse is the opposite request, pushed only on a successful answer) and is unchanged; journaling it on a timeout could make rollback report a failure ("not active") for a stream request OBS never applied, and stream sequencing in rollback belongs to TASK-079. The inverse is also journaled when the throw is "not connected" or a send failure (request never reached OBS); restoring a value that never changed is harmless.
