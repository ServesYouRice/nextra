TASK-047 (lane package, commit 8960f5f on lane/package): on Windows, run() in scripts/package-app.js no longer passes shell: true. npm ci runs as node plus npm_execpath and caxa as node plus its bin script, so their arguments never go through a cmd.exe line; any other command goes through a cmd.exe line in which every argument is double-quoted. Lint, typecheck and npm test pass (1065 tests, 0 failures; tests/packageApp.test.js 62, of which 14 are new). Not done: the approval-gated packaging run in the prompt's verify list (`node scripts/package-app.js` from a folder whose path has a space, expecting Nextra.exe and Nextra.exe.sha256). The brief says not to run the packager, which runs npm ci and downloads cloudflared and FFmpeg.

Choices the prompt left open or where I differed:
- The builder is buildPackagerCommand(command, args, { platform, env, execPath, resolveCaxaBin }) and returns { command, args, shell: false, windowsVerbatimArguments }. run() passes it the merged child env. Off win32 it returns the command and arguments as given (npx caxa and npm stay as they were on macOS).
- npm_execpath is used only when it is an absolute path to npm-cli.js. Under npx, pnpm or yarn it points at their own entry point, which cannot run `npm ci`; then, and when it is not set (a direct `node scripts/package-app.js`), npm goes through the quoted cmd.exe fallback, which runs npm.cmd from PATH as before. The npm ci arguments are fixed and need no quoting; cwd is passed to spawnSync, not on the line.
- caxa's bin comes from the "bin" field of its package.json, as step 1 says. caxa's "exports" exposes only its entry module, so require.resolve('caxa/package.json') fails. getCaxaBinPath walks up from require.resolve('caxa') to the package.json named caxa. If caxa is missing the packager now fails with "caxa is not installed (it is a devDependency; run npm install first)". Before, npx would have fetched an unpinned caxa from the registry.
- Fallback (step 2): cmd.exe /d /s /c "<line>" with windowsVerbatimArguments, the same form Node uses for shell: true. It is given ComSpec (looked up case-insensitively in the env copy) or cmd.exe. Each argument is wrapped in double quotes and trailing backslashes are doubled, because otherwise `"C:\dir\"` would end with an escaped quote for the child's argument parser. Arguments with ", %, ! or CR/LF throw a clear error instead of being escaped (line breaks were not in the prompt's list; a line break ends a cmd.exe command).
- Something the prompt did not foresee: if the fallback quotes a bare command name (`"npm" ...`), npm.cmd breaks. A batch file started by a quoted bare name gets %~dp0 = the current directory, and npm.cmd finds npm-cli.js through %~dp0. A real check failed with "Cannot find module ...\Temp\node_modules\npm\bin\npm-prefix.js". A bare name of [A-Za-z0-9._-] therefore stays unquoted (it cannot hold a metacharacter), and a command given as a path is quoted. The test 'run passes them unchanged to a .cmd shim found by its bare name through PATH' covers this; it fails when the name is quoted.
- One small visible difference: caxa now embeds the node that runs the packager (process.execPath). Before, caxa.cmd started whichever node was on PATH. Under `npm run package` they are the same node.
- Unchanged, as the constraints ask: writeSbom and findCloudflaredOnPath (fixed arguments, still shell: true on win32), smoke-packaged.js, the manifests, the caxa argument list in main(), and the error text "<command> failed with code <status>".
- Real checks done, all with version-only commands (no install, no download): node + npm-cli.js --version (10.9.2), the cmd.exe fallback `npm --version` through npm.cmd (11.6.0, the globally updated npm that npm.cmd picks), and run('npx', ['caxa', '--version']) through the real run() (3.0.1). The committed caxa test starts the real caxa CLI with a missing --input path. caxa reports that path verbatim and exits before it copies or runs anything. No test starts the real npm: the npm tests use a stand-in npm-cli.js, and the route is asserted before anything is spawned.
